## 一、文档体系与工程纪律

本项目文档体系以**单一真相源（Single Source of Truth, SSOT）**为设计准则，所有开发、维护与扩展遵循以下纪律：

1. **架构与业务规则**：任何核心子系统（音频引擎、动画引擎、状态机、题库格式）的规范变动，必须同步维护在 [总体架构.md](./总体架构.md)；
2. **变更留痕**：每次代码迭代、版本发布或关键缺陷修复，必须在 [CHANGELOG.md](./CHANGELOG.md) 中以倒序表格形式留痕；
3. **零外部服务依赖原则**：本工程为纯静态幼教单页应用，一切改动必须维持“全离线运行、双击即可秒开、零跨域限制”的基本原则。

## 三、工程模块覆盖范围

项目采用轻量级前端原生技术栈（Vanilla HTML/JS/CSS），不依赖重量级前端框架，各子系统划分如下：

| 模块类别 | 对应路径 / 文件 | 核心职能说明 |
| :--- | :--- | :--- |
| **主界面与控制层** | [`index.html`](../index.html) | 单页 Hash 路由、UI 渲染、答题状态机、交互事件处理、设置面板 |
| **学科题库层** | `data_*.js`（共 9 个文件） | 识字、数学、加减法、图形颜色、动脑筋、科学、安全好习惯、儿歌古诗、英语磨耳朵 |
| **静态离线音频库** | [`audio/`](../audio/)（547 个 MP3） | 预生成的微软晓晓高保真标准 MP3 音频，覆盖全站读题、解析、古诗、欢迎词 |
| **TTS 生成工具链** | [`extract_tts_texts.js`](../extract_tts_texts.js)<br>[`generate_tts.py`](../generate_tts.py) | 题目文本自动提取与 edge-tts 批量高并发离线音频生成工具 |
| **动画播放器** | [`anim/anim-player.js`](../anim/anim-player.js) | 基于 Remotion + React 打包的单文件离线数学动画讲解播放器 |
| **动画工程源码** | [`anim-src/`](../anim-src/) | Remotion 数学动画工程源码，支持 9 类数学题型参数化实时渲染 |
| **持续集成与部署** | [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) | GitHub Actions 自动化静态发布至 GitHub Pages |

## 四、核心避坑指南（开发必读）

| 典型问题 | 根本原因与现行标准方案 |
| :--- | :--- |
| **微信浏览器听不到声音？** | 微信 WebView 的 `window.speechSynthesis` 为空壳对象；且第三方外部 TTS 会被防盗链或 Range 跨域拦截。<br>**现行方案**：采用 `audio/` 目录下的同源静态 MP3 文件，通过单例 `Audio` 播放，微信原生 100% 兼容（详见 [总体架构.md](./总体架构.md) 第 4 节）。 |
| **修改音频后部署没有更新？** | `pages.yml` 打包时必须显式拷贝 `audio/` 到 `_site/`，微信客户端如果存在顽固缓存，访问时在 URL 尾部添加 `?v=N` 即可强制刷新。 |
| **移动端长题目配图被截断？** | 部分数数题物品过多（如 10 颗糖果），使用单行固定字号在小屏设备会被屏幕边缘裁切。<br>**现行方案**：内置 `measurePicWidth` 动态测量计算算法，自动缩小字号；若极限情况下字号仍超标则自适应折行。 |
| **重新构建动画如何生效？** | 在 `anim-src/` 下 `npm run build` 生成新版 `anim/anim-player.js` 后，必须在 `index.html` 中的引用地址递增版本号参数（如 `anim-player.js?v=4`），避免客户端强缓存。 |
| **代码执行发生 TDZ 异常白屏？** | 严禁在脚本顶层未经安全判断直接执行依赖未声明变量的函数。所有媒体加载操作严格采用**惰性初始化（Lazy Initialization）**。 |
